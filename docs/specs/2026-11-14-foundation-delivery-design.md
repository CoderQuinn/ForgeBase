# ForgeBase foundation delivery

Status: implementation authorized on 2026-11-14 for the bounded first foundation batch. Tracks [#13](https://github.com/CoderQuinn/ForgeBase/issues/13).

Baseline: main `d89b90198305541c7390e20ae8c521830f52e8b9`. Borrowed readable windows and payloadBuffer assembly are already implemented. Keep these APIs and the compatibility materialize fallback; final owned output still copies payload bytes.

## Required behavior

Extend the existing UDP builder benchmark to compare Data, borrowed contiguous window, nonzero/nested slice and legacy materialize fallback against an independent IPv4/UDP byte oracle. Oracle validates complete bytes including lengths/checksum/ports/payload; using the old builder as the sole oracle is insufficient. Preserve the historical baseline comparison when its exact source is available; shallow/missing history must fail clearly, never substitute HEAD. Sizes include 0, 64, 1472, 4096 and 65507; reject 65508. Current validation precedence remains unchanged.

Machine-readable results record schema version, baseline/candidate SHA, dirty flag, toolchain/OS/architecture, executable digest, fixture digest, raw batch-duration samples and copy/materialize observations with explicit measurement method. Do not label batch timing as per-packet p99 or assert unmeasured allocation/zero-copy/HEV performance. Baseline and candidate must pass the oracle before timing is eligible. Dirty runs may be diagnostic only and must be labeled; release/performance qualification rejects dirty evidence. Script option details may be frozen by implementer in this doc before coding.

A clean Git URL consumer must compile the borrowed API at exact main/candidate revision and demonstrate that old v0.3.0 lacks the new API; no tag creation. Existing boundary tests already cover requested cases: reuse them instead of duplicating. Add tests only for new benchmark validation/provenance behavior or uncovered genuine contracts. README documents ownership and rollback to the compatible copy path/previous consumer pin.

No checksum/IPv6/public buffer API expansion. Rollback is the benchmark/consumer tooling commit; consumer lock selection is recorded, not automatically changed.


## Frozen harness interface (Task 1)

`bash Scripts/benchmark-udp-builder.sh --output PATH` runs correctness only by default. `--measure` enables native Release timing; `--smoke` uses 2 rounds, 10 iterations and 2 warmups instead of 7 rounds, 20,000 iterations (2,000 for 65,507 bytes) and 100 warmups. `--allow-dirty` permits explicitly diagnostic evidence; otherwise tracked or untracked changes reject before building. `--baseline SHA` defaults to `d5a75c766871436619b8fb431567b7d7ebf2d839` and must name an available full commit containing the historical builder. Missing objects fail with an explicit fetch prerequisite. No HEAD substitution. `--self-test` additionally runs oracle corruption checks without timing. `--profile-check DIR` compiles the benchmark with Swift coverage instrumentation, exercises both timing-order branches using smoke-sized batches, and retains its executable/profile in DIR; this is correctness coverage and never native performance qualification. Unknown options reject.

JSON schema version 1 has `provenance` (full baseline/candidate SHA, dirty Boolean, baseline source SHA-256, benchmark source SHA-256, executable SHA-256, fixture SHA-256, Swift version, OS, architecture, build flags), `qualification` (`diagnostic_dirty`, `instrumented_correctness`, `correctness_only`, or `native_measurement`), and `result`. The result contains `oracle_passed`, `timing_status`, `fixture_sha256`, `observations`, `workloads`, and `sink`. Each workload records payload size, candidate path (`data`, `borrowed`, `nested_slice`, `legacy_fallback`), iterations and raw round entries with execution order and separate baseline/candidate batch-duration nanoseconds. Empty round arrays mean `not_run`; no fabricated duration. Fixture identity is SHA-256 of the ordered synthetic payload bytes at sizes 0/64/1472/4096/65507. Source and executable digests identify the actual benchmark inputs. Observations are counted outside timing using a synthetic forwarding buffer: scoped borrow override count, default-fallback materialize count, and final owned-output payload bytes, the last derived from validated payload length and source contract, not allocator instrumentation. This is not an allocation measurement. Baseline and each candidate path must match a separately encoded complete IPv4/UDP packet for ports 0, 1234 and 65535 before any timing. A 65,508-byte payload must reject. Self-test flips every byte in reference packets and requires oracle rejection.

`FORGEBASE_BENCHMARK_TEST_RESULT=PATH python3 Scripts/test-udp-builder-benchmark.py` verifies CLI fail-closed behavior, provenance validation and a fresh native correctness/self-test artifact. Without the environment variable the artifact check is explicitly skipped. `python3 Scripts/test-udp-builder-consumer.py --revision SHA --output PATH` uses a clean temporary SwiftPM consumer with the public `https://github.com/CoderQuinn/ForgeBase.git` URL (no package path override), pins and asserts `Package.resolved` and actual checkout HEAD/clean status, compiles both public products and the new borrowed API, and expects that API compilation to fail at exact `v0.3.0` commit `d1f6656ef8f674277484ca54237a0eeb40c8b3c3`. The coordinator may push the isolated candidate branch before this exact HTTPS proof; only the coordinator performs that external action. Reports contain public repository identities and exact pins, never local/private repository paths.

Coverage audits retain the existing first-party production gate and report its exact Swift/C executable numerator/denominator. No production code is planned to change, so changed production executable coverage is N/A (0/0); benchmark/tooling executable coverage is audited separately and any unmeasured scope remains explicit. Correctness instrumentation is separate from native timing. The coordinator grants a serialized slot before `--measure` is used.
